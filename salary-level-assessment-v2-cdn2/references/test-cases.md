# 验收案例

## A. 输入校验

### A1 口径不明确

输入：`北京，后端开发工程师，5年，25K`

- 该轮唯一输出必须是：“25K是税前固定月薪吗？是否包含奖金、补贴、股票或其他收入？”
- 确认前检索、计算、结构化 JSON 和网页生成调用数均为 0。
- 用户回答“是税前固定月薪，不包含其他收入”等同义信息后，不再追问，立即完成一次性检索并默认生成单文件 HTML。

### A2 四项完整

输入：`北京，后端开发工程师，5年，税前固定月薪25K，不包含奖金、补贴、股票或其他收入`

- 直接完成一次性检索并生成单文件 HTML，不重复确认。
- 不追问公司、学历、成果、技能、目标或跳槽计划。

### A3 合并追问

输入：`后端开发，月薪25K`

- 一轮合并追问城市、工作年限和薪资口径。

## B. 单一数据源与默认交付

- 首次运行完成全部检索、计算、筛选和链接核验后保存一份结构化 JSON。
- 输入确认并完成一次性检索后，默认生成 HTML；输出目录只新增指定的 `index.html`。
- 不另附 JSON 或 Markdown 文件；对话正文在一句简短结论和一个 HTML 文件或托管网页链接之后，按固定顺序显示五个原生 Markdown 入口，不重复完整第一轮报告。
- 不向用户展示或附加结构化 JSON、Markdown 文件、测试报告或截图。
- 页面内嵌公开 JSON 与输入 JSON 的业务结果一致，但不含非脉脉链接、平台字段或内部证据字段。
- 三轮使用相同 `run_id` 和 `generated_at`。
- 页面运行时除本地 HTML 外不请求薪资、职位、帖子或 JSON 数据。
- 使用第二份变体 JSON 渲染时，城市、岗位、年限、薪资、职位和讨论均随数据变化，且模板中不存在第一份示例事实。

## C. 第 1 轮：今日在职性价比

- “今日在职性价比”和“高薪的坑位都在挑什么人？”分别位于两个连续、独立的结果区；最上方评估标题继续读取 `data.result.headline`。
- 今日在职性价比区展示四项用户信息、明确位置、平均报价、月薪参照差额和 12 个月等额差额，并且只展示薪资周报入口。
- 高报价要求区展示恰好三类真实职位支持的要求，并且只展示高薪机会入口。
- 两个入口不得位于同一链接区域；“带薪摸鱼1分钟，继续看看真话与好岗”和“1 听同岗同行真话”“2 看今日在招匹配好岗”只在两个结果区之后展示。
- 不展示完整帖子、完整职位、综合诊断卡或报告图片；桌面端薪资周报二维码不属于报告图片，可以展示。
- 数据说明最多一行，风险说明只显示“以上为公开招聘报价参照，不代表实际涨薪或录用结果。”
- 390x844 视口下核心结果约一屏，恢复二维码后最多 1.3 个视口；不得靠固定高度裁切。

## D. 分支与最大轮次

分别从新页面验证：

1. 同岗同行真话 -> 生成今日跑路可行性诊断卡；
2. 今日在招匹配好岗 -> 生成今日跑路可行性诊断卡；
3. 同岗同行真话 -> 再看今日在招匹配好岗；
4. 今日在招匹配好岗 -> 再听同岗同行真话。

每条路径要求：

- 第 2 轮正确展示所选分支；
- 第 1 轮不自动滚动；第 2 轮渲染后平滑滚动到可见位置；第 3 轮定位到当前轮次消息顶部；
- 直接生成综合卡时，第 3 轮只用短摘要补齐未看分支；
- 补看另一分支时，第 3 轮完整展示另一分支并在同轮末尾生成综合卡；
- 第 3 轮不直接跳到综合诊断卡或页面底部，综合卡仍可继续向下滚动查看；
- 最大轮次严格等于 3，完成后不再提供继续到第 4 轮的按钮。

## E. 同岗同行真话

网页标题为 `{岗位}同行近期的真实处境与真话`；第 3 轮短摘要前缀为“同岗同行真话速览：”。

使用“北京，后端开发工程师，5年”及确定性候选夹具验证：

1. 路径级 `site:` 查询无结果或结果不足时继续域名级 `site:` 查询。
2. 搜索宿主返回“不支持 `site:`”时跳过其余 `site:` 层，执行普通“脉脉 + 关键词”搜索。
3. 每个查询步骤只有一个 `theme_id`，不把薪资、跳槽、团队强度、晋升和奖金合并成一条全量查询。
4. 5年以上后端讨论团队是否卷、工作强度是否大，即使没有薪资数字也可以作为同岗环境内容入选。
5. HR 讨论期望薪资、Offer 和谈薪空间可以作为招聘方视角入选。
6. HR 概括必须保留“HR认为”或“招聘方观察”等主体限定，个人观点不得写成全市场统计。
7. 城市不匹配只影响排序，不自动淘汰正文、岗位和主题均合格的帖子。
8. 核验日向前超过24个月的帖子必须淘汰；恰好处于24个月边界的帖子可以保留。
9. 页面只有月日且年份未核验时不得直接认定时间合格。
10. `sitemap_lastmod` 只能单独记录，不能代替 `published_at`。
11. `content_evidence_source` 不是详情页正文或使用了未登录不可读评论时必须淘汰。
12. 三条合格脉脉帖子已经存在时不得调用外部来源；不足三条时才允许外部内容补足。
13. 一条、两条和三条讨论均能生成 HTML 并正常渲染，零条或四条由生成器拒绝并交给上游降级。
14. 搜索穷尽后只有一条或两条时按实际数量显示，不隐藏、不补造。
15. 帖子收集与筛选前后 `salary_market` 和 `result` 必须完全一致，帖子涨幅或薪资数字不得进入薪资计算。
16. 非脉脉内容不显示平台名称、域名和外链。
17. 脉脉帖子只显示与内部 `source_url` 完全一致、且路径属于帖子详情页的真实链接。
18. HTML 和降级文字结果直接使用同一份 `discussions[].summary`，不得分别改写。

所有概括仍须只有一句，优先保留正文中的人物背景、数字、结果、差距、现实问题或争议；不得出现证据摘要腔、虚构选择、虚构原因、伪避坑指南或评论区推断。帖子列表后只展示“去脉脉社区看更多职场讨论”，不得混入其他承接入口。

## F. 今日在招匹配好岗

- 网页标题为“看今日在招匹配好岗”；第 3 轮短摘要前缀为“今日在招匹配好岗速览：”。
- 展示 `featured_job_ids` 指定的二至四个职位。
- 每个职位含公司、岗位、城市、招聘薪资、经验要求、月薪区间参照差额和关键门槛。
- 只有脉脉职位显示同一个职位详情链接；其他职位不显示平台名称和外链。
- 岗位列表后只展示“去脉脉找工作看内推机会”，不重复展示高薪机会入口，也不声称自动滚动到人脉区域。
- 明确职位只是按城市、岗位和经验初筛，不承诺用户符合全部要求。

## G. 今日跑路可行性诊断卡

- 包含用户信息、薪资结论、当前固定月薪、平均报价、月薪参照差额和高报价方向摘要。
- 卡片外标题为“今日跑路可行性诊断卡”，卡片内主标题为“今日宜离职跑路吗？先看这份行情底牌”。
- 按“今日在职性价比、高薪坑位门槛、同岗同行真话、找同岗熟人内推、看看前同事去向”展示五个独立结果区，每区只有一个对应入口。
- 不存在统一的链接集合区，五个入口均紧跟各自结论。
- 前一个分支承接入口之后存在至少 32px 的留白、顶部细分隔线和带 `final-section-heading` 类的卡片外标题；标题下一兄弟节点是综合诊断卡。
- 卡片最底部只出现一次“恭喜完成今日“电子裸辞”体验！”结束语，并复用 `data-note` 次要说明样式。
- 薪资周报和前同事去向二维码均由本地生成并编码对应短链接。
- 桌面、移动端和豆包窄预览中，两个 App 入口都同时显示二维码、“请使用手机扫码，在脉脉App内查看”和对应链接文字。
- `max-width: 640px` 媒体查询不得隐藏薪资周报或前同事去向二维码。
- 前同事说明不得声称 Skill 已读取用户脉脉资料，不预告具体人员、人数或平均薪资。

## I. 直接打开与响应式

- `examples/index.html` 通过 `file://` 直接打开，控制台和页面无错误。
- 桌面 1440x1000、移动 390x844、窄屏 360x800 和 520px 豆包窄预览均无横向溢出。
- 两个 App 二维码在上述所有视口均可见、保持正方形且能从最终 HTML 解码为对应固定短链。
- 按钮最小高度 44px，中文、数字、链接、二维码不截断、重叠或溢出。
- 外链是蓝色文本链接，内部轮次选择是按钮，两者不存在嵌套或样式混用。
- HTML 不包含 `target="_blank"`、其他 `target` 新窗口配置或 `window.open`。
- 移动端五个结果区纵向单列，不把不同入口并排展示。
- “跑路可行性”“今日在招”不得生成离职评分、宜忌判断、涨薪承诺或脱离结构化职位证据的今日在招结论。
- 正式页面不出现“当前漏斗进度”“重新体验”“演示说明”等评审辅助区。

## J. 默认交付与极端降级

正常情况下：

- 输入确认后默认生成单文件交互 HTML；
- 对话正文只显示一句简短结论、一个 HTML 文件或托管网页链接，以及其后的五个固定原生 Markdown 入口；
- 不展示 `salary-data.json` 或其他 JSON 文件；
- 不展示 Markdown 文件、测试报告、截图或完整文字报告；
- 不展示浏览器测试、JSON一致性、无网络请求、交叉验证、证据链、数据抓取、校验、数据脱敏、二维码完整性、运行环境或其他技术说明；
- HTML 内链接是辅助展示，对话正文中的五个原生 Markdown 链接是附件预览中的主要跳转入口。

宿主明确不支持文件或 HTML、HTML 生成失败，或者宿主无法返回网页文件或托管链接时：

- 使用同一内部 JSON 输出最多三轮普通文本对话；
- 保留相同分支、固定链接和第 3 轮综合诊断卡；
- 不生成 Markdown 附件；
- 不声称已经生成网页；
- 不重新检索或计算。

## K. 真实性与措辞

- 招聘报价只用于公开招聘市场参照，不写成在职员工薪资排名。
- “能涨多少”不落为实际涨薪承诺；统一使用“参照差额”。
- 不编造职位、帖子、数据、样本量或链接。
- 搜索失败时不使用模型记忆补造内容。
- 职位检索依次使用带本次运行 Unix 毫秒时间戳的脉脉职位 CDN、脉脉公开职位网页、脉脉公开详情搜索和其他公开来源；每层按城市、岗位和相近经验执行同一有效性标准。
- 内部证据保留真实平台、标题、链接、核验时间和匹配情况。
- 用户可见文本和 HTML 公开载荷中，非脉脉来源不显示平台名称、Logo、域名、来源标签或外部链接。
- 用户报告不得出现“猎聘”“职友集”“BOSS直聘”“智联招聘”“前程无忧”等非脉脉平台名称。

## L. 目录与格式

- 开放 Agent Skills 格式校验通过。
- `SKILL.md` 中全部引用文件存在。
- CDN 2.0版不存在本机绝对路径、待办标记或遗留的未替换渲染标记。
- 原项目Skill和原安装版修改前后的完整文件 SHA-256 清单完全一致。

## M. CDN职位获取、详情核验与降级

使用依赖注入的 HTTP、网页、浏览器和搜索夹具验证，不真实等待九十秒，不把实时职位总数写成永久断言：

1. Skill名称、目录和包名均为 `salary-level-assessment-v2-cdn2`，展示名称为“今日宜离职跑路吗”，一级标题为“今日宜离职跑路吗 CDN 2.0版”。
2. 新目录来自现有 CDN 版本完整复制；四个受保护原目录修改前后全量文件清单和 SHA-256 一致。
3. CDN 稳定基础地址为 `https://s.taou.com/n/platform/job-list.min.json`，本身不带查询参数。
4. 给定固定测试时间戳时，精确生成 `https://s.taou.com/n/platform/job-list.min.json?v={timestamp}`。
5. 默认使用系统时钟生成 13 位正整数 Unix 毫秒时间戳；零、负数、浮点、非安全整数及非 13 位值均拒绝。
6. 同一次运行只生成一次动态地址，普通抓取、原始 HTTP、失败重试和证据 `dataset_url` 全程复用。
7. 普通 `web_fetch` 失败转原始 HTTP 时不得重新生成时间戳；原始 HTTP 成功不进入后续来源。
8. 不同运行使用不同系统时刻时能够生成不同动态地址。
9. 源码和文档不要求任何固定 `v` 值，也不写死后端示例时间戳，不回退到无参数地址。
10. 动态 `v` 只作缓存键，不进入 `dataset_updated_at`；后者只读取 `Last-Modified` 或数据集真实字段。
11. 动态 `v` 不进入职位 `published_at`；后者只读取详情真实 `datePosted` 等原始字段。
12. CDN下载失败、JSON损坏、`columns`/`rows`无效或缺少必要字段时进入 `maimai_public_page`，再按原顺序进入详情搜索和外部来源。
13. `columns` 顺序打乱后仍能正确映射 `rows`，并读取 `sourceId`、`description` 等必要字段；不得硬编码列位置。
14. `45k-75k·16薪` 解析为 45000、75000 和 16；固定月薪中点为 60000，薪数不进入平均报价计算。
15. `50k以上`、面议、缺少一侧范围和无法可靠解析的薪资不进入薪资样本。
16. 职位网页只能读取少量职位时保留已有记录并继续 `maimai_detail_search`；脉脉职位不足时才调用 `external_public_search`。
17. `sourceId` 生成 `https://maimai.cn/n/job/geo/{sourceId}`；详情同一性失败或不可读时不展示详情链接。
18. 获取方式仍只允许 `maimai_cdn`、`maimai_public_page`、`maimai_detail_search`、`external_public_search`；CDN记录不得伪装成 `browser_ui`。
19. 非脉脉职位继续隐藏平台、域名、来源标签和外链，已核验脉脉职位保留真实详情链接。
20. 新获取流程前后月薪中点、算术平均、月薪参照差额、差额比例、十二个月等额差额和区间位置公式及字段名保持不变。
21. 三轮状态机、第三轮滚动、五个固定链接、二维码、HTML视觉样式、帖子规则和默认交付方式保持不变。
22. HTML模板和成品页面不执行CDN请求、职位搜索或详情核验，动态内部地址不进入用户公开载荷。
23. CDN 2.0项目版和安装版全量文件一致，二者均通过开放 Agent Skills 格式校验。

实时网络抽查只检查当次 `rows.length > 0`、同一时点网页声明数量与CDN数量一致、网页首屏职位ID存在于CDN，以及少量详情字段一致；不得固定具体职位数量。
