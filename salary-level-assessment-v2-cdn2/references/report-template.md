# 三轮交互报告模板

## 统一原则

- 输入确认并完成一次性检索后，默认生成单文件交互 HTML；HTML 和极端降级文本都读取同一份内部结构化 JSON。
- 内部 JSON 不作为用户附件，也不附带 Markdown 文件；默认交付单文件 HTML，并在对话正文提供五个原生 Markdown 入口。
- 浏览器只展示和切换状态，不重新搜索、抽样、计算或判断。
- 页面最多三轮。第 3 轮必须收口到综合诊断卡，不能再出现进入第 4 轮的操作。
- 缺失字段直接隐藏，不显示空卡、模板变量、检索过程或完整证据块。
- 结果中的“差额”均指公开职位报价参照差额，不代表用户真实可涨金额。
- “今日宜离职跑路吗”“今日跑路可行性”“今日在招”只作为界面包装，不新增离职评分、宜忌判断、涨薪承诺或未经核验的今日在招结论。

## 第 1 轮：今日在职性价比

首屏按以下顺序渲染两个独立结果区：

1. **今日在职性价比**：展示 `{城市}｜{岗位}｜{工作年限}｜税前固定月薪{金额}`、明确位置判断、当前固定月薪、公开样本平均报价、月薪参照差额和按 12 个月等额差额；结果说明后展示薪资周报入口。所有视口同时展示二维码、“请使用手机扫码，在脉脉App内查看”和“在脉脉App查看完整薪资周报”链接文字。最上方评估标题仍直接读取 `data.result.headline`。
2. **高薪的坑位都在挑什么人？**：展示三类由真实职位支持的高报价要求；要求之后展示“对照这些要求，看看同城同岗有哪些职位正在给出更高报价。”以及“查看同城同岗高薪机会”。
3. 两个结果区全部结束后，显示“带薪摸鱼1分钟，继续看看真话与好岗”，再展示网页内部选择：“1 听同岗同行真话”“2 看今日在招匹配好岗”。

薪资周报和高薪机会必须分别位于对应结果区内，不能放进同一个链接区；外链使用蓝色文本，内部选择使用按钮。

首轮不渲染报告图片、PNG、完整帖子列表、完整职位列表或证据块；桌面端薪资周报二维码可以正常展示。移动端从结论到两个选择应控制在一屏左右，不能用固定高度裁切内容。

数据说明最多一行。逐职位发布时间已经充分核验时使用：

> 数据参考：近12个月公开职位｜有效样本X个｜核验时间：YYYY-MM-DD

没有充分核验逐职位发布时间时使用：

> 数据参考：当前公开职位快照｜有效样本X个｜核验时间：YYYY-MM-DD

不得用CDN文件更新时间、HTTP `Last-Modified`、sitemap `lastmod` 或抓取时间冒充职位发布时间。

固定风险说明：

> 以上为公开招聘报价参照，不代表实际涨薪或录用结果。

## 第 2 轮 A：同岗同行真话

网页标题固定为 `{岗位}同行近期的真实处境与真话`；在第 3 轮仅补短摘要时，前缀固定为“同岗同行真话速览：”。

展示一至三条本次真实检索且正文、发布时间均已核验的帖子概括。搜索穷尽后不足三条时按实际数量展示，不隐藏已有内容。每条只用一句话，优先把人物背景、具体数字、现实问题和异常反差放在前面；只有原帖事实支撑时才增加自然问题钩子，没有合适钩子时直接以具体结果结束：

```text
1. {人物背景 + 具体数字或反差 + 可选的真实问题钩子}
   {仅脉脉帖子显示“查看原帖”链接}
```

不得使用证据摘要式开头、虚构最终选择、原因揭晓、真相反转或避坑指南。HTML 和降级文字对话必须直接读取同一份内部 JSON 中的 `discussions[].summary`，不得在渲染阶段重新概括。

帖子列表之后展示“去脉脉社区看更多职场讨论”。该入口是社区推荐页，不得声称已经筛选同城同岗内容。末尾提供：

- `2 再看今日在招匹配好岗`
- `3 生成今日跑路可行性诊断卡`

非脉脉内容不显示平台名称和链接。

## 第 2 轮 B：今日在招匹配好岗

网页标题固定为“看今日在招匹配好岗”；在第 3 轮仅补短摘要时，前缀固定为“今日在招匹配好岗速览：”。

展示二至四个 `featured_job_ids` 指定的已核验职位。每个职位包含：

- 公司和岗位；
- 城市；
- 招聘薪资及薪数；
- 经验要求；
- 与用户当前固定月薪的区间差额；
- 关键匹配门槛。

职位列表前说明：这里只按城市、岗位和经验做初筛，具体门槛需用户对照真实经历。脉脉职位可以显示同一职位详情链接；其他职位不显示平台名称和外链。

岗位列表后只展示“去脉脉找工作看内推机会”，不重复展示第 1 轮已经承接高报价要求的高薪机会入口，也不得声称链接会自动滚动到人脉内推区域。入口前展示：“想进一步接触这些高薪机会，可以去脉脉找工作看看内推机会。”末尾再提供网页内部选择：

- `1 再听同岗同行真话`
- `3 生成今日跑路可行性诊断卡`

## 第 3 轮：补齐并收口

### 直接生成综合卡

用户从第 2 轮直接选择生成时，先显示未查看分支的 `branch_summaries` 短摘要，不完整重复该分支的所有帖子或职位，然后展示综合诊断卡。

### 补看另一分支

用户在第 2 轮选择另一个分支时，第 3 轮完整展示该分支，并在同一轮末尾附综合诊断卡。不能增加第 4 轮。

### 今日跑路可行性诊断卡

卡片按结论拆成五个独立结果区，每区只保留一个对应入口：

1. **今日在职性价比**：当前固定月薪、公开职位样本平均报价、月薪参照差额及薪资周报入口。HTML 在所有视口同时显示二维码和 App 链接文字。
2. **高薪坑位门槛**：三类高报价方向摘要及高薪机会入口。
3. **同岗同行真话**：一句同行实况摘要及同行讨论入口。
4. **找同岗熟人内推**：一句人脉承接说明及内推人脉入口。
5. **看看前同事去向**：资料使用说明及前同事去向入口。HTML 在所有视口同时显示二维码和 App 链接文字。

卡片外标题固定为“今日跑路可行性诊断卡”，卡片内主标题固定为“今日宜离职跑路吗？先看这份行情底牌”。前一个分支承接入口结束后，先留白，再显示细分隔线和卡片外标题；标题与卡片之间保持明确间距，不新增消息或轮次。不得把五个入口重新合并为底部链接列表。每个结果区使用独立小标题和细分隔线，入口紧跟对应内容；移动端保持单列。

模块五之后、卡片内部最底部只显示一次：

> 恭喜完成今日“电子裸辞”体验！人可以先继续搬砖，心记得每天过来刷刷同岗新报价和好机会

前同事说明固定为：

> 进入脉脉后，可根据你在脉脉填写的职场资料查看前同事去向；本 Skill 未读取你的脉脉资料，也不在站外预告具体人员、人数或平均薪资。

## 对话正文与降级

正常完成后，对话正文只输出一句简短结论、一个托管网页链接或单文件 HTML，并在其后按以下顺序输出五个原生 Markdown 链接。HTML 内链接只作辅助展示；不重复第一轮内容，不输出完整文字报告或技术说明。

[在脉脉App查看完整薪资周报](https://taou.cn/x/nosfnMiG)

[查看同城同岗高薪机会](https://maimai.cn/n/platform/job-list)

[去脉脉社区看更多职场讨论](https://maimai.cn/community/home/recommended)

[去脉脉找工作看内推机会](https://maimai.cn/n/platform/homepage/jobs)

[在脉脉App查看前同事去向](https://taou.cn/x/nosfnAJf)

仅当宿主明确不支持文件或 HTML、HTML 生成失败，或者宿主无法返回网页文件或托管链接时，以普通文本完成相同的三轮状态机：

1. 第 1 次回复输出“今日在职性价比”和两个编号选择；
2. 第 2 次回复按用户选择输出同行或岗位分支；
3. 第 3 次回复按上述补齐规则输出另一分支的短摘要或完整分支，并输出综合诊断卡。

降级对话中的链接使用标准 Markdown。不得生成 Markdown 附件，不得写“网页已生成”、不得生成第 4 轮，也不得重新检索或计算。
